# Second Surface delivery plan

## Product invariant

One accepted five-tool registry drives live WebMCP registration, the visible
reference, deterministic findings, artifact previews, and tests. Agent calls may
inspect, audit, stage, and preview. Only visible developer controls may accept,
reject, or reset.

## Delivery checklist

- [x] Preserve the previous feature branch and its uncommitted work.
- [x] Create `feat/second-surface` from `main`.
- [x] Inventory the contract registry, generator, Explorer, controller, tests,
  and deployment delta.
- [x] Implement the accepted registry and seeded contract problems.
- [x] Implement deterministic audit and lightweight schema example validation.
- [x] Implement staged structured revisions and visible human review.
- [x] Register the five Second Surface WebMCP tools through the existing lifecycle.
- [x] Generate registration metadata, contract JSON, Markdown, and OpenAPI 3.1.
- [x] Promote the editorial Contract Explorer into the root workbench.
- [x] Replace old product copy and generated fixtures.
- [x] Run docs, typecheck, lint, tests, build, browser checks, and leak scan.
- [x] Commit and push the isolated branch.
- [x] Deploy an isolated preview.

## Explicit cuts

No JSON import, URL scanner, browser extension, GitHub import, account system,
cloud persistence, arbitrary code execution, external model call, marketplace,
workflow canvas, or additional sample catalog.
